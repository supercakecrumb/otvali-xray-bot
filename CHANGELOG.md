# Changelog
All notable changes to this project will be documented in this file.

## v0.2.5 - 2026-10-19

* Make Mini App Finland retrieval existing-only so deleted or never-provisioned clients are not recreated; preserve the legacy bot issuance path.
* Read actual managed/legacy readiness without provisioning and expose stable disabled/not-found states separately from provider outages.
* Cover deleted-client revocation, first-provisioning denial, inactive state and distinct-account key isolation.

## v0.2.4 - 2026-10-19

* Add an optional authenticated Telegram Mini App API with short-lived signed launch data, exact origins, no-store responses and bounded requests.
* Reuse the bot's subscription identity and current managed profiles; retain legacy Finland with numeric ownership checks and shared issuance locking.

## v0.2.3 - 2026-10-19

* Restore the simple Russian main menu, one subscription for all managed routes, and a separate keys submenu retaining legacy Finland.
* Export managed standalone keys from the same account and subscription, with private eligibility checks and opaque callbacks.
* Shorten installation to three steps, add `/help_setup`, and place optional routing under installation with configurable public website links.

## v0.2.2 - 2026-10-19
### Changed
* Replace legacy platform help and server-key delivery guidance with English Happ/INCY instructions and official download links.
* Distinguish single-server keys from refreshable subscriptions and show existing setup/routing guides only to eligible accounts.
* Redact credential-delivery transport failures from legacy key diagnostics.
* Default new managed access to unlimited traffic with no automatic expiry, retaining explicit finite access periods and unchanged existing-account retrieval.

## v0.2.1 - 2026-10-19
### Changed
* Show the Stockholm subscription flow in English, with Happ/INCY setup guidance and the existing Finland profile as a fallback.
* Add private setup/routing guides and optional app routing profiles for Russian traffic directly and remaining traffic through the VPN.
* Offer Moscow routes through the same VPN subscription, preserving existing direct Finland access.

## v0.2.0 - 2026-10-19
### Added
* Optional Remnawave Stockholm subscriptions for explicitly approved bound Telegram IDs, alongside existing Finland access.
* Durable provider mappings, idempotent issuance and safe private-chat delivery.
### Changed
* Require Stockholm access to be disabled before deleting its bot account.
* Suppress credential-bearing Telegram transport diagnostics.
* Pin the tested build/runtime, run without root, and add a database-backed runtime healthcheck.

## Security hardening

Verify pre-provisioned SSH host keys; reject unknown and changed keys. Restrict user workflows to their private Telegram chat, fail closed on identity/database errors, and redact command arguments and panel responses from logs. Exclude local credentials and Git history from Docker build contexts and remove the checked-in executable. Provision verified known_hosts before deployment.
