## v0.2.18 - 2026-10-30

* Fix first-time Telegram proxy issuance failing while the provider applies a newly created user: wait briefly for runtime admission with read-only checks, without holding locks, and re-check before activating the route; disabled or changed users keep their existing revocation and conflict handling, and administrator revocation is not delayed by the wait.
* Open the Telegram section with personal links for every available route in one message, so several proxies can be added at once and switched if one stops working. All routes are created before waiting for admission, so the first open takes about as long as the slowest route. Offer a refresh when some routes are temporarily unavailable; route buttons from earlier messages open the same view.
* Add `POST /api/miniapp/telegram/proxies/all` for the Mini App with the existing authentication, exact-origin, no-store and request limits.

## v0.2.17 - 2026-10-30

* Reduce the Russian home menu to subscription, installation, Telegram and help; keep VPN checks, account access, feedback and Mini App in secondary screens.
* Shorten subscription/key delivery and split device selection and optional routing details into focused screens, preserving existing legacy Finland credentials.
* Add working parent/home navigation to keys, QR images and status screens, including text navigation from a Telegram photo.
* Support `start=status` and `start=telegram` deep links while retaining both bot identities and the existing private MTProto provider.
* Add an opt-in offline export of fictional user screens for reproducible interactive previews.

## v0.2.16 - 2026-10-30

* Add four authorized private Telegram MTProto routes with personal credential issuance and individual revocation.
* Keep provider management behind authenticated SSH transports and retain existing VPN subscriptions, legacy keys and account permissions.

## v0.2.15 - 2026-10-29

* Support the new Telegram bot alongside the existing bot, sharing current users, subscriptions and VPN keys while keeping owner alerts on the primary bot.
* Accept Mini App launch signatures from either configured bot and open the beta form from the `start=beta` invitation link.
* Scope support-message references and activity events to their bot identity, so overlapping Telegram IDs cannot misroute administrator replies or merge activity counts.
* Preserve historical message and activity data through additive schema changes; deliver administrator replies through the bot where the conversation began.
* Require successful polling from every configured bot for runtime health, tolerate transient failures, and stop all pollers on permanent or sustained failures.

## v0.2.14 - 2026-10-29

* Open the testing form from `/beta` and the bot menu; preserve existing subscriptions and individual keys.

## v0.2.13 - 2026-10-26

## Security hardening

Verify pre-provisioned SSH host keys; reject unknown and changed keys. Restrict user workflows to their private Telegram chat, fail closed on identity/database errors, and redact command arguments and panel responses from logs. Exclude local credentials and Git history from Docker build contexts and remove the checked-in executable. Provision verified known_hosts before deployment.
